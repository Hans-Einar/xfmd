# XFMD — process adoption mandate

Project Owner instruction, 2026-09-25: initialize XFMD's own SDP area, migrate its
conversation board to SDP KanBan and register the subsequent adoption/design work
for another agent. This is a process assignment, not a new set of product features.

XFMD's existing purpose is a lightweight Markdown viewer/editor and companion to
xfw/xfi. [Product requirements](../../xfmd_requirements.md) retain current needs
and acceptance. [KB-XFMD-017](../KanBan/active/%23017--Proposal--Adopt-SDP-and-model-XFMD.md)
will inventory stakeholders/actors from actual sources and distinguish owner
requirements from reconstructed design. Do not infer an exhaustive stakeholder
list from this bootstrap.

Owner clarification, 2026-09-29: #017's SDL baseline should make functionality,
responsibilities and dependencies explicit so later SDP navigation and diagram
preview do not produce uncontrolled architectural growth. The latest refinement also selects
SDUI where feasible, with labeled editor/preview areas instead of full widgets. SDUI's intended role is early requirements
exploration and exercising SDL before native implementation. See the current
[MaintenancePlan](../Maintenance/MAINT-XFMD-0004.md#owner-scope-clarification--2026-09-29).
