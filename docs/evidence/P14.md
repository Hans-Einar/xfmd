# P14 — tabeller og inputretting

## M1: musegrab og lenkemarkør

PointerTest feilet før rettingen på `!app.host->grabbed()` etter vanlig
venstre press/release gjennom X11 og FOX-dispatch. FoxRenderHost overstyrte
release uten å kalle ungrab, mens press arvet FXWindow::grab. Høyre/midt-release
kunne frigjøre denne grabben. Dette forklarer en konkret låsevei; fysisk touchpad
og alle mulige gesturesekvenser er ikke bevist uttømmende.

Preview eier nå press/release for alle tre knapper, balanserer grab før callback,
og avviser chord, drag, foreldet frame og release uten tilsvarende press.
Ingen paste i read-only preview; editorens normale paste beholdes.

Unicode ↗ erstatter Cairo-bueprimitiven for HTTP(S), formes/måles med Pango og
tegnes identisk i preview/PDF, uten understrek gjennom markøren.

Release: PointerTest, NavigationGuiTest, RendererTest, TypographyTest og
PdfFidelityTest bestod (5/5). PointerTest dekker gjentatte 1/2/3-klikk,
alle kombinasjoner av to knapper, release utenfor og stale preview.

## M2: GFM og native tabellayout

cmark-gfm 0.29.0.gfm.13 er hashpinnet i bootstrap, kontrollert ved configure og
koblet statisk. Bare table-utvidelsen kobles til parseren. Registrering gjøres
én gang via C++ static-init; preview og eksport bruker egne parserinstanser.
Tabellmodellen kopierer rader/celler/justering og kildeområder uten cmark-pekere.

TableLayout bruker innholdsmål og headerbredde for kolonner, gjenbruker InlineLayout
for celler og produserer de samme DrawRuns/Decoration som PDF allerede tegner.
Rader holdes samlet; header holdes med neste rad når gruppen får plass. Grensene
og bevisst manglende headerrepetisjon er beskrevet i README og krav.

Kontroller: escaped pipe i code span, Unicode og eksakte/tilnærmede kildeområder,
bold/link/center/right, tomme/ujevne rader, tabell i sitat, ufullstendig tabell,
65-kolonnegrense, for høy A4-rad, lang tabell, `.txt` og andre extensions av.
TablePreviewTest avdekket også en eksisterende host/renderer-uenighet ved preview
smalere enn 40 points; de bruker nå samme minstebredde, så preview blir interaktivt
selv når splitteren gjør den svært smal.

Den utvidede PDF-fidelitytesten inkluderer 80 tabellrader med Unicode, bold og
HTTP(S)-markør. Alle rader og ↗ finnes i PDF-teksten, og rasterkontrollen består.
Etter siste bredderetting bestod PointerTest/TablePreviewTest/PdfFidelityTest/
TableTest (4/4). PointerTest bekrefter nå også frigjøring før lenkecallback,
undertrykking av orphan/chord/drag/stale og faktisk Editor-verktøylinjeklikk etterpå.

[Native tabeller og Unicode-lenkemarkør](P14-tables.png) er visuelt kontrollert
under isolert Xvfb. Ingen handlinger i brukerens aktive X11-sesjon.


## M3: samlet kontroll, minneprofil og installasjon

Release bestod 35/35 tester (67,75 s); ASan/UBSan med lekkasjekontroll bestod
33/33 (69,05 s). To strace-feiltester kjøres bare uten sanitizer.

Ytelsessjekken fant GUI-peak 103 964 KiB, litt over SR-011. Et forsøk med mindre
reserve for DrawRuns hjalp ikke og ble forkastet. Deling av Cairo/FOX-pikselbuffer
løste heller ikke denne toppen og ble forkastet. Sluttkoden beholder P13s testede
FoxCairoCanvas. Massif viste at TextProjection alene hadde omtrent 40 MiB i
samtidige offset-vektorer under gjenoppbygging (gamle kart + kapasitetdobling).
TextProjection reserverer nå raw-lengde + terminaloffset og tekstkapasitet før
løkken. Dette endrer ingen byte-/BOM-/CRLF-mapping eller editoratferd.

Etter rettingen bestod Document/Workspace/Presentation/Pointer/TablePreview/
ExportGui (6/6), og de samme seks bestod også ASan/UBSan med lekkasjekontroll
etter rettingen (7,52 s). Endelige [målinger](P14-measurements.txt), samme 1 MiB-corpus:

- 30 varme kjøringer: **p95 93,28 ms**, headless peak **61 476 KiB**.
- Første native visning: **236,13 ms**, GUI peak **85 784 KiB** (83,8 MiB).
- Tidlige tidsmålinger varierte 87–117 ms p95 under aktiv desktop på batteri.
  Siste måling rapporteres; dette er ingen påstand om garantert hastighetsøkning.
  SR-011s 100 ms / 500 ms / 100 MiB-terskler er ikke endret.

Installasjon til ~/.local er utført med atomisk binærbytte. Installert binær
matcher Release byte-for-byte, desktop-entry er validert. Eksisterende XFMD-
prosess er beholdt, og brukeren åpner programmet på nytt for ny kode.

Fysisk gesturesekvens er ikke uttømmende testet, men den konkrete grab-feilen er
reprodusert før retting og dekket etterpå. Tabellheaderrepetisjon, gigantiske
rader over sideskift og andre GFM-utvidelser er uttrykkelig utenfor P14.
