# P9 — Tekniske avklaringer

Baseline: design-merge `6d550ca`. AlmaLinux 10, FOX 1.6.57, lokal Window Maker-fork.

## P9-M1 — Input og fullscreen

Eksisterende WheelGuiTest driver både ekte X11 Button4/5 → FOX og syntetiske
code=1/30/120-events. Den kjøres som baseline-regresjon. Diagnostikk kan aktiveres
med `XFMD_TRACE_WHEEL=1 xfmd fil.md`: hver mottatt hendelse logger akse, code,
tid og modifikatorer, aldri dokumenttekst. Core-FOX forblir inputvei. Fingerantall
og fingerløft er ukjent, og testgenererte smådeltaer beviser ikke fysisk oppløsning.
Ingen automatisk fysisk touchpadbevegelse er utført; brukerens hardware-tuning
kan gjøres i Preferences etter P10 uten å blokkere implementasjonen.

`tests/probes/FullscreenProbe.cpp` er bygget med `c++ -std=c++17 ... -lX11` og
kjørt via `tools/run_with_xvfb.py python3 tools/run_with_wmaker.py ...`.
Første kjøring feilet på ugyldig WM-argument. Etter retting til --dont-restore
og --static bekreftet den isolerte Window Maker-instansen inn- og utgang gjennom
_NET_WM_STATE_FULLSCREEN. Baseline CTest: 19/19 bestått (42,50 s). Brukerens desktop ble ikke berørt.

Review: ingen raw input-grab; eksplisitt skille mellom syntetiske og fysiske
inputbevis. EWMH virker, men produksjonsadapterens geometri/modal-policy testes i P13.
